## 已完成（0.6.34：待办页 + 命令面板）

起因是一句用户的实话：「桌面端的操作较多，比如更多操作里，就有好几个」。

| 维度 | 问题 | 处理 |
|---|---|---|
| 信息架构 | 侧栏「更多操作」`<details>` 里平铺 **8 个**动作，四种性质混在一起：只读磁盘（扫描/强制扫描）、网络批处理（刮削/翻译）、**写磁盘**（同步 NFO/清理空目录）、改数据结构（修正内容类型）、视图导航（整理预览） | 侧栏只留「库级」动作（扫描 / 强制扫描 / 修正内容类型 / 改名 / 删除）；批处理与写磁盘各归各的页面 |
| 重复 | 扫描既是主按钮又在「更多」里；整理预览既是 tab 又是按钮 | 各留一处 |
| 顺序感 | 8 个按钮同权重，人不知道先干哪件；而这些动作在库里有天然顺序（认 → 刮 → 翻 → 整理 → NFO） | 新增**待办**页并设为默认：每行 = 动词 + 「还剩多少」+ 一个按钮，第一行有数字的标「建议先做」 |
| 危险度 | 写磁盘的动作和安全动作并排 | 行上标 `只读 / 网络 / 写磁盘`；写磁盘的三项都走「先列清单再确认」，入口在整理预览页 |
| 可发现性 | 112 个按钮只有铺在界面上才找得到 | `Ctrl K` 命令面板：13 个动作可搜、↑↓ 选、Enter 执行、Esc 关，禁用项按当前状态灰掉并写明原因 |
| 启动成本 | 一进来是 3,883 行的条目列表 | 待办页的数字分批取：便宜的（数行/数目录）先回，贵的（整理计划要读磁盘、NFO 差异要读 sidecar）随后补 —— 首页不能为了一个可选数字在移动硬盘上卡半秒 |
| tab | 5 个平级 tab（条目/未识别/整理预览/任务/设置） | 3 个（待办 / 条目 / 任务）+ 齿轮；未识别与整理预览变成待办行的去向 |
| tab（修正） | 一次性页面切走就回不去 —— 在整理预览看清单，切到任务看进度，再回来只能绕回待办，且计划要重算 | 按"打开过的页面"处理：进过一次就挂在 tab 条上（带 ×），切到别处也能点回来，状态（计划/勾选）不丢；× 关掉就回待办 |

## 界面自查（不用人肉点）

渲染层有 GPU 问题时 `x11grab` 也会拿到黑图，所以走主进程的 `capturePage`：

```bash
cd apps/desktop && KURA_DATA_DIR=/tmp/库 KURA_SCREENSHOT=/tmp/ui.png KURA_SCREENSHOT_DELAY=3000 \
```

## 不跟的项（有理由，不是漏做）

### 1. display 字体 —— 不引

技能建议标题用 display 字体做对比。Electron 内置字体有限，引外部字体文件要多背几百 KB 且中文回退不可控。
**克制方案**：靠字重 + 字距 + 字阶拉开层级，已经够用。

### 1. 触控目标 44px —— 不跟

按钮实际高度 31–33px，低于 Apple HIG 的 44px（那个数字是给触屏的）。
这是桌面鼠标应用，32px 是 Windows/macOS 桌面工具的主流高度；跟 44px 会让侧栏和工具栏白白胖一圈。
**若将来支持触屏**：整体放大到 40px+ 并重排工具栏。

### 2. 动效

只有 `translateY(1px)` 与行 hover 120ms 过渡。技能要求"动效有意义"——但工具类应用里动效过多反而干扰。
**决定：保持接近静态，只在状态切换处给 120–200ms。**
