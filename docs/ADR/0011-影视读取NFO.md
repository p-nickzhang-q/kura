# ADR 0011 — 影视域也读 NFO，但只读身份与内容字段

- 状态：已采纳
- 日期：2026-11-11
- 修订：[ADR 0008](0008-扩域-影视库.md) 决策 6「影视的 NFO 只写不读」

## 背景

ADR 0008 决策 6 的理由是：

> 影视的 nfo 是 **Emby/Jellyfin 会自己写**的（标记已看、自定义集名），回读等于把播放器的内部状态当元数据吸进库里。

这条理由在**写**的方向上依然成立，但它顺带把另一件事也堵死了：**换电脑**。

两个域的恢复能力当时就是不对称的：

| | av 域 | video 域（修订前） |
|---|---|---|
| 扫描时 | 从文件名认番号 → 自动建条目 | 只登记文件，不建条目 |
| 换电脑后 | 扫一遍 + `nfo sync` 读回 → 全恢复，零网络 | 库里空 → 必须重新找建议 + 绑定 + 刮 |
| 为什么能/不能 | 番号在文件名里 | 身份是 TMDB id，文件名给不出 id |

用户的原话是「我拿刮削好的盘，接到另一台电脑上」。把整个 `%APPDATA%\kura` 拷过去
能解决一时，但那是"把库搬过去"，不是"从盘上恢复库" —— 换一台没碰过 Kura 的机器、
或者库被误删了，就没有退路了。

## 关键发现

**身份就在文件里。** 我们自己写出去的 nfo 一直带着：

```xml
<uniqueid type="tmdb" default="true">46198</uniqueid>
```

ADR 0008 担心的「播放器状态」是另外一批标签，它们和 Tmdb id 是两回事：

- 身份与内容：`<uniqueid type="tmdb">`、`<tmdbid>`、`<title>`、`<originaltitle>`、
  `<plot>`、`<premiered>`、`<studio>`、`<runtime>`、`<genre>`、`<actor><name>`、`<season>`/`<episode>`
- 播放器私有状态：`<playcount>`、`<watched>`、`<resume>`、`<lastplayed>`、`<userrating>`、`<dateadded>`

回读前者不会污染库；回读后者才会。

## 决策

### 1. 影视域读 nfo，但解析器**只认白名单字段**

`domain/nfo-tv-read.ts` 的 `ParsedTvNfo` 类型里根本不存在播放状态字段 —— 不是"读进来再过滤掉"，
而是**类型上就没有**。这样"回读把播放器状态吸进库"在实现层面不可能发生，不依赖后来者记得这条规矩。

### 2. 恢复是显式动作，不是扫描的副作用

扫描依旧**不建条目、不改内容**。待办页多一行：

```
00  从 NFO 恢复   168 条   只读   [恢复]
    盘上的 nfo 带着 TMDB id —— 换电脑不用重新刮, 元数据直接读回来
```

点下去先干跑（数清多少剧/多少电影/多少文件），主进程弹原生确认框，确认后才动库。
与 ADR 0002 §5「organize 默认 dry-run」同一套节奏：先看清单再执行。

排序放在 `00` 也是刻意的：它一次性消掉「未识别」和「待刮削」两行，不是日常流程的第几步。

### 3. nfo 是种子，只填空字段

与 av 域 `syncNfo` 完全一致：库里已经有值的字段一律不动，`field_sources` 也不会把
网络来源改写成 `nfo`。盘上的 nfo 可能是半年前的快照，用它覆盖刚刮的数据就是把新数据换成旧的。

### 4. 只处理未绑定的文件

`media_files.number is null` 是范围。已经绑定的条目说明库里知道身份 —— 那是 `nfo sync`
和刮削的事。这样重复执行天然幂等，也不会跟 `nfo sync` 抢同一批行。

### 5. 没有 TMDB id 的 nfo 不猜

读不出 id 就列进 `noTmdbId`，不拿目录名去猜。猜错身份比找不到更糟（ADR 0008 决策：
影视 v1 不自动匹配）。那批目录仍然走「找建议」。

## 后果

- 换电脑：扫描 → 待办页「从 NFO 恢复」→ 点一下，**零网络**恢复条目、绑定、季集、集名。
- 换盘（盘符变了）：还是先 `library relocate` 改库根，再走这条路 —— 两条是互补的：
  relocate 保住已有索引，recover 重建索引。
- Emby 改写 nfo 后我们的字段被冲掉怎么办：下次 `nfo sync` 会把库里的值写回去（本来就是
  字段级 merge，不整份覆盖）。
- 集名/简介从集级 nfo 读回来写进 `episodes`（`field_sources` 记 `nfo`）。`episodes` 表仍然
  只装"来源声明的集"，nfo 就是一种来源。
- 不做的事：不自动恢复、不读播放状态、不从文件名猜身份。
