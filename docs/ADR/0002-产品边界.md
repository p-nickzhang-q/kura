# ADR 0002 — 产品边界与可扩展接缝

- 状态: 已接受(2026-10-27)
- 前情: [ADR 0001](0001-栈选择.md)(桌面壳、core 语言、无守护进程)

## 产品定义

**番号制的本地影片库管理器**。磁盘上一堆认不出名字的文件 → 有番号、有元数据、有正确存放位置的条目 → 交给 Emby/Jellyfin 播放。

对标 Amane(MDCx 的继任者),但**范围大幅收缩**:

| 能力 | Amane | Kura v0.1 |
|---|---|---|
| 扫描入库 | ✅ | ✅ |
| 多源刮削 + 逐字段择优 | ✅ 40+ 源 | ✅ 3 源(接口就绪,实现分批) |
| 整理归档 | ✅ | ✅ 默认 dry-run |
| NFO / 海报落盘 | ✅ | ✅ NFO |
| 演员一等实体 | ✅ | ❌ 先存字符串 |
| RSS 订阅 / 定时任务 | ✅ | ❌ |
| 助理 Agent(自然语言) | ✅ | ❌ |
| 播放反代 / 超分 | ✅ | ❌ |
| Docker / 多用户 | ✅ | ❌ |
| 桌面壳 | Swift + .NET + Kotlin | Electron(仅 Windows) |

## 决策

### 1. 先做 AV 域,但留三条接缝(而非通用抽象)

core 只承认三个任何"文件 → 元数据 → 归档"形态都有的接缝:

```
identify(输入)        → ItemKey      纯函数, 无 IO
fetch(ItemKey)        → RawFields[]  每个 Source 一次, 并发
materialize(Metadata) → Plan         纯函数, 无 IO
```

- **不引入** `Item{domain,key}` 的通用实体、不做 EAV、不做 JSON 万能字段。
- 扩到第二个域(TMDB 电影、游戏 ROM、本子)时,新增的是**另一套 Domain 实现**(独立的解析规则、字段表、来源、模板变量),共用的是 `Library` / `MediaFile` / `Plan` / 任务语义。
- **不做的代价必须写在这里**:扩域时 `items` 表要么加 `domain` 列,要么按域分表。当前按"加 `domain` 列 + 域内字段各自建表"预留,不改现有设计。

**为什么不做通用抽象**:字段强类型是列表筛选、字段锁定、字段来源的前提;通用化的直接后果是查询退化为 JSON 扫描。Amane 的 40 个源都没逼它做通用抽象,我们没有理由提前做。

### 2. 内容类型在建条目时落定,不可改

判定顺序固定:`fc2` → `uncensored`(6 位-3 位)→ `amateur` → `chinese` → `western` → `censored`。
理由见 Amane `docs/dev/data-model.md`:类型决定刮削路由,可漂移会让同一番号的元数据在多次刮削间跳变。

### 3. 无番号条目用 `site:id` 作为身份

素人、国产大量无番号。与真番号**分命名空间**(`javdb:2x9k1` vs `ABC-123`),不混排、不互相匹配。

### 4. 三个动作互不触发

`scan` / `scrape` / `organize` 是三个独立命令。没有"扫描后自动刮削"、"刮削后自动整理"。
理由:自动串联等价于隐式任务系统,而任务系统是 v0.1 明确不做的;GUI 里由用户点击串起来。

### 5. ORGANIZE 默认 dry-run

`kura organize <library>` 只输出 `Plan`;`--apply` 才动磁盘,GUI 里必须点确认。
这是唯一不可逆的操作。`Plan` 同时是 CLI 与 GUI 的共享输出,不存在"界面能预览、命令行直接执行"的不一致。

### 6. 没有 watch

**CLI 不提供常驻监控。** GUI 打开期间用 `fs.watch` 监听库目录;关闭即停。
需要定时的用户用 Windows 任务计划程序调 `kura scan`。
这是 ADR 0001"只在执行时运行"的直接推论,后续任何"加个 watch 命令"的需求都要先推翻那条。

### 7. 演员先存字符串数组

v0.1 `actors` 是 `string[]`,规范化(去空格、繁简、别名)在写入时做。
v0.2 升表时:`actors` 表 + `metadata_actors` 关联,按规范化名字合并。当前不建表,是因为别名/头像/人物刮削是独立子系统的量,而字符串数组不挡路。

## 后果

**得**:范围可在一到两周内跑通;每个动作都能离线测(纯函数 + 录制 fixture);CLI 与 GUI 行为不可能不一致(同一份 `Plan`、同一份 core)。

**失**:
- 3 个来源之外的站点需要逐个补,且站点改版=维护债。这是本类产品的固有成本,不是设计缺陷。
- 没有自动串联,用户要按顺序点三次(或让 agent 按顺序调三次)。
- 无番号条目的匹配能力天生弱于有番号条目。

## 何时推翻

- **要多人/多设备共享同一库** → 需要真服务端,ADR 0001 与本文同时作废。
- **要第二个域且字段差异极大** → 优先按域分表,不要加 JSON 万能列;届时新写 ADR。**已发生**:普通影视域见 [ADR 0008](0008-扩域-影视库.md)(本文的产品定义与七条决策仍然有效,只是「番号制」收窄为库的一个域)。
- **要"打开就自动跑"** → 引入任务系统 + 常驻进程,推翻本文第 6 条与 ADR 0001 第 5 条。
- **要公开分发** → 站点合规风险与维护成本需要单独评估,可能需要砍掉内置源改为纯插件。
