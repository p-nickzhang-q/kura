# ADR 0007 — 演员是一等实体（但只做索引）

- 状态: 已接受(2026-10-30)
- 前情: [ADR 0002](0002-产品边界.md)（演员实体明确留到 v0.2 之后）、[CONTEXT](../../CONTEXT.md) 的「演员身份」

## 背景

演员一直是 `items.actors` 里的一个 JSON 字符串数组。够用，但有两个问题：

1. **没法"点演员看全部"**：要按演员找作品只能 `like '%名字%'`，而名字里有没有空格、全半角写法不同都会漏。
2. **同一个人分裂**：`吉沢 明歩` 与 `吉沢明歩` 在数据里是两条不同的字符串。

现在有 108 个演员、116 条关联的真实数据可以验证，值得建表了。

## 决策

**建实体表，但只做索引，不做别名体系。**

| 做 | 不做（明确砍掉） |
|---|---|
| `actors(id, name, normalized unique)` | 别名表 `actor_alias` |
| `item_actors(number, actor_id, position)` | 头像 / 人物页刮削 |
| `normalizeActorName`：NFKC + 去空白 + 小写 | 繁简/异体字自动归并 |
| 迁移里一次性回填历史数据 | 懒回填 |
| `item list --actor` 过滤 + 界面点演员名跳转 | 独立的「演员」页面 |

三条关键的取舍：

### 1. 索引是**派生**的，单向

`items.actors` 仍是快照的一部分，`item_actors` 从它重建（`syncItemActors`）。
反向不写回：索引坏了重扫一次就自愈，而"两处都能写真源"迟早会不一致。

这也是为什么 `{actor}` / `{actors}` **仍取快照原文**：索引的显示名是"首次出现的写法"，
拿它拼目录会让路径跟着索引顺序漂移 —— 与 ADR 0003 拒绝按译文建目录是同一个理由。

### 2. 规范化只做可解释的三件事

NFKC（`ｱｷﾗ` → `アキラ`、全角字母 → 半角）、去所有空白、小写。

**刻意不做的**：繁简与异体字归并。`吉沢明歩` / `吉澤明歩` 在 JIS 层面就是两个名字，
自动归并要靠别名表，而"这两个名字是不是同一个人"是判断题 —— 人才能答。
先看真实数据裂到什么程度，再决定要不要建表；现在就建等于凭想象设计。

### 3. 回填在迁移里，不懒加载

schema v8 的迁移后用 `AFTER_MIGRATIONS[8]` 跑一次 `backfillActors`（NFKC 在 SQL 里做不了，必须回代码层）。
条目只有几百条，一次拆完；懒回填会让"有的条目靠 JSON、有的靠索引"长期并存，查询要写两套。

## 备选与放弃原因

| 方案 | 为什么不选 |
|---|---|
| 规范化后的名字**写回** `items.actors` | 快照失真；下次刮削又被源数据覆盖，等于白改 |
| 现在就连别名表一起建 | 没有真实的分裂数据支撑，表结构与合并策略都会建错 |
| 直接把名字当主键 | 改名（合并）时要级联改所有关联，且名字不是稳定的身份 |
| 独立的「演员」页（头像墙） | 只是过滤 + 跳转就能拿到 90% 的用处，多一个页面多一份维护 |

## 后果

- 已知缺口：`吉沢明歩` 与 `吉澤明歩` 仍是两个人（javbus 给简体、javdb 给繁体，分裂几乎必然）
- `{actor}` 的目录名不受索引影响，换名字典/合并别名**不会**导致文件搬家
- 删除条目时 `item_actors` 靠外键级联清掉；重刮后没人指向的演员由 `pruneActors` 回收
- 演员名只在大写/空白层面归一，所以 `Yua Mikami` 与 `yua mikami` 是同一个人，但 `YuaMikami` 与 `Yua Mikami` 也是 —— 这是想要的
