# ADR 0003 — 整理维度、多值与"已整理"判定

- 状态: 已接受(2026-10-29)
- 前情: [ADR 0001](0001-栈选择.md)(进程模型)、[ADR 0002](0002-产品边界.md)(域边界)

## 背景

"整理能否按演员、按 tag 分成几种维度?" 这个问题下面藏着三件事，不能一起答：

1. **一个视频能不能出现在多个位置**；
2. **多值字段（演员、tag）怎么落进单个路径**；
3. **整理过的文件如何不再被整理/刮削**。

## 决策

### 1. 一个库一个维度，维度只决定第一层

预设：番号 / 演员 / 片商 / 厂牌 / 系列 / 类型 / 年份。模板负责其余层级（`{actor}/{year}/{number}`）。
落库存**展开后的模板字符串**，不存预设 id：否则改预设定义会让已有库的行为漂移，这类问题极难排查。

### 2. 单位置，不做多位置链接

一个视频只落一个路径。**明确不做**硬链接/符号链接铺开：
- Emby/Jellyfin 按文件扫描，不去重，同一部片会出现多条；
- 跨盘（NAS/FUSE）链接直接失败；
- 索引行数翻倍，"文件即事实"的前提被破坏。

（Amane 有 `link_template` 与 `organize/link.py`，能力存在，但本产品不需要多位置带来的复杂度。）

### 3. 多值：`{actor}` 与 `{actors}` 并存

用户既要"一个演员名的文件夹"，又要"多值全拼"。这两个诉求用一个开关表示不了，用两个占位符就能：
`{actor}` 取第一（默认预设用它），`{actors}` 顿号拼全部。与 Amane 的 `{actor}` / `{actors}` 一致。

### 4. 不做按 tag 整理

tag 是**多值且易变**的：只取一个会漏掉其余 tag 的影片，全拼会让目录名膨胀到超路径上限，
且 tag 由来源决定、随时可能增删 —— 路径跟着变，就要反复搬文件。
Amane 的模板变量里同样没有 tag。字段层面 `tags` 仍然保留并写进 NFO `<tag>`，只是不参与整理。

### 5. 用幂等 + 冲突检测替代"整理完成"目录

不做物理"已完成"目录（Amane 也没有）。判定改为：

| 目标状态 | 行为 |
|---|---|
| `free` | 移动 |
| `same`（目标就是源，含硬链/软链） | skip，视为已就位 |
| `occupied`（目标被别的文件占着） | **skip，绝不覆盖** |
| `unknown`（stat 失败） | skip，不当作占用 |

"整理过的文件不再被刮削"不实现：刮削按番号走，与文件位置无关；按目录决定是否刮削会把状态编码进路径，
模板一改就全错。

### 6. 旧成品库用库级开关保护, 不靠"完成目录"

已有整理好结构的库, 需要的是**不动文件**, 而不是"把 NFO 抄进库"。所以:
`libraries.organize_enabled = 0` → `scan` 照常索引、`scrape` 照常可用, 但 `organize` 短路(不算计划、不动盘)。
CLI: `library add <名> <目录> --no-organize` / `library set-organize <库> --no-organize`。

为什么不导入 NFO: 字段是子集、无 `field_sources`、分不清是谁写的、会形成 DB → NFO → DB 回路。
用户若需要旧库的元数据, 重新刮削一次即可(幂等, 且不覆盖锁定字段)。

## 后果

**得**：维度是一个显式枚举，可枚举、可测试；路径只在用户主动改模板时才变；覆盖风险被显式拦在 plan 阶段。

**失**：一部多演员的片只会在第一演员目录下出现（想要"每个演员都有"就得上链接，本 ADR 明确拒绝）；
按 tag 浏览只能靠 GUI 筛选，不能靠目录。

## 何时推翻

- **要按 tag 整理** → 必须先回答"多值维度如何单值化"（取第一？投票？手工指定主 tag？），
  这是一个产品决策，不是实现细节；在此之前不加 `{tag}` 占位符。
- **要"收件/成品"分离** → 那是**两个媒体库**，需要先实现跨库移动（当前目标强制在库根内），不要用"完成目录"打补丁。
- **要多位置** → 先解决重复扫描与跨盘问题，再引入链接模板。
