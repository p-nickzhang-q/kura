# ADR 0004 — 翻译（日 → 中）

- 状态: 已接受(2026-10-29)
- 前情: [ADR 0002](0002-产品边界.md)(域边界)、[ADR 0003](0003-整理维度.md)(路径稳定性)

## 目标

把日文**标题**与**简介**翻成简体中文；演员名不翻。翻译失败不得阻断刮削。

## 决策

### 1. 覆盖显示值，原文另存

`items.title` / `items.plot` 存**译文**（Amane 同款：译文写入标量字段，`raw` 保留源语言快照）。
额外存 `title_original` / `plot_original`，因为本产品有 Amane 没有的需求：**目录名要靠它稳定**。

- NFO：`<title>` = 译文，`<originaltitle>` = 原文。
- 占位符：`{title}` = **原文**（路径稳定），`{title_zh}` = 译文。
  这是对 Amane 的有意偏离：它的模板不依赖标题，我们依赖。

### 2. 只翻含假名的日文

判据是「含平假名/片假名」。纯汉字的日文（标签、人名）不在范围内；中文/英文原样不动。
简繁转换不做（需要额外依赖 zhconv），将来要加也应走确定性转换而不是 LLM。

### 3. 演员名不翻

两个原因：
1. 人名音译没有唯一答案（葵つかさ 是"葵司"还是"葵梓"？），翻了反而更难搜；
2. `{actor}` 是目录名第一层，译文漂移会导致**整批文件搬家**。

Amane 同样不翻人名（"纯汉字日文只出现在词级（标签/人名），不在翻译范围"）。

### 4. OpenAI 兼容端点 + temperature 0

只配 `baseUrl` / `apiKey` / `model` 三项，一份配置通吃 DeepSeek、通义、Ollama、LM Studio、OneAPI。
`temperature = 0`：译文是**派生数据**，同一原文翻出两个结果属于 bug，不是创意。

### 5. 缓存独立成库

`dataDir/translations.db`，纯缓存、可随时删、不进主库迁移：
键 = `sha256(源文本) | 目标语言 | 字段 | sha256(系统提示词)`。
不含 model（换模型想重译时删文件即可），含提示词指纹（改提示词自动失效）。
同一键的并发请求只发一次（coalescer）。

### 6. 触发：开关自动 + 手动补

`config set --translate` 决定刮削后是否自动翻；`kura translate --pending` 补历史条目。
配置缺 `baseUrl`/`model` 时翻译器为 `null`，刮削照常进行并打一行警告。

## 后果

**得**：Emby/Kodi 里显示中文标题、简介，同时 `originaltitle` 保留日文可回溯；重刮不重复烧 token；路径不会因为翻译而变。

**失**：
- 数据库里 `title` 不再是站点原文（要看原文得读 `title_original` 或 `snapshots`）；
- 翻译质量取决于模型；人名、专有名词可能译错，且无法批量纠正（只能逐条 `item set` + 锁定）；
- 多一层 `translations.db` 需要用户知道"删了会重翻、重翻要花钱"。

## 何时推翻

- **要做繁中/多语言** → `title` 单列不够，需要 `translations(item, field, lang)` 表；届时改名 + 数据迁移。
- **要翻演员名** → 必须先解决"译文不稳定导致目录改名"：要么锁定首译结果，要么目录永远用原名。
- **要离线/本地翻译** → 只要兼容 OpenAI 端点（如 Ollama）即可，无需改代码。
