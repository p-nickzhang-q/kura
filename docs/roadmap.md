# 路线图（延后项）

> 这不是愿望清单，而是**已经想清楚、但明确决定先不做**的东西。每条都写了为什么延后、以及什么时候该捡起来。
> 决策依据见 `docs/ADR/`，词汇见 `CONTEXT.md`。

## 一、大概率先做的

### 1. 文件监控（watcher）

**要解决**：下载完新片要手动点「扫描」。
**为什么延后**：与 ADR 0001「只在执行时运行」直接冲突。ADR 0002 第 6 条已定：**只在 GUI 打开期间**用 `fs.watch` 监听，CLI 不提供常驻监控。
**做法**：GUI 启动时对每个库的根目录挂递归监听 → 去抖（同一批文件只触发一次）→ 复用 `scan` 的登记逻辑，只处理新路径。
**坑**：Windows 的递归 `fs.watch` 在大目录上会吃掉句柄；`scan` 目前是全量遍历，需要加"只处理指定路径"的入口。

### 2. 清理与回收站

**要解决**：删文件只能手动；删错了没救。
**为什么延后**：它是唯一会**删除**用户数据的动作，比 organize 更危险，需要独立设计（ADR 0002 未覆盖）。
**做法**（对齐 Amane 的 `SCAN_INVALID` + `DELETE`）：先产出"清理清单"（无效文件 / 空目录 / 小文件 / 黑名单命中），人确认后才删；删除一律移动到 `.kura_trash` 而不是 `unlink`。
**坑**：跨盘移动会退化成复制；清单必须可 diff、可重放。

### 3. 无番号条目（素人 / 国产）

**要解决**：中文名、无番号的影片现在全部进「未识别」，永远刮不了。你的 `D:\Download\h` 那 16 个就是这种情况。
**为什么延后**：需要定"没有番号时用什么当身份"。
**做法**：CONTEXT 里已经定义了 `site:id` 命名空间（如 `javdb:2x9k1`）；`scan` 需要接一条路径：识别不出番号时，允许用「站点 + 站内 ID」建条目；CLI 补 `file set-number <路径> --number ...` 手动指定。
**坑**：`site:id` 条目不能参与番号去重；`{number}` 占位符对它们要回退到站点 ID。

## 二、想做但成本更高的

### 4. 人物一等实体（Actor）

**要解决**：现在演员是字符串数组，没有别名合并、没有头像、不能"点演员看全部作品"。
**为什么延后**：ADR 0002 明确留到 v0.2 之后；别名解析 + 头像 + 人物刮削是独立子系统的量。
**做法**：`actors` 表 + `metadata_actors` 关联 + 按规范化名字合并；先做"索引与跳转"，不做头像刮削。

### 5. 订阅源（RSS）

**要解决**：新片发现要从站点抓，而不是等下载。
**为什么延后**：抓 RSS + 定时拉取需要调度；没有守护进程时只能靠系统计划任务（`schtasks` / `cron`）。
**做法**：`feeds` 表 + `feed_items` 去重 + `kura feed fetch`；由用户自己挂计划任务。

### 6. 来源插件化

**要解决**：加一个站点要改代码（`sources/builtin.ts`）。现在只有 3 个源，硬编码还划算。
**为什么延后**：插件接口一旦公开就是长期契约，我们还没有第二个第三方源来验证它。
**做法**（对齐 Amane 的 `plugin/`）：`Source` 接口 + 数据目录 drop-in + 每个插件声明支持的 `contentTypes` 与配置项。

## 三、明确不做（有条件的）

| 项 | 原因 | 何时推翻 |
|---|---|---|
| 服务端 / 多用户 / 远程访问 | ADR 0001：本地优先，无守护进程 | 要多人共享同一个库时 |
| 多位置硬链接（每个演员目录都有副本） | ADR 0003：Emby 会把同片扫成多条、跨盘失败 | 先解决重复扫描问题 |
| 内置助理 Agent（自然语言查库） | 方向不同：外部 agent 直接调 CLI | 需要非技术用户时 |
| 按 tag 整理 | ADR 0003：多值易变，目录名爆炸 | 先回答"多值怎么单值化" |
| 播放器 / 转码 | 不是本产品的职责，交给 Emby/Jellyfin | 不做 |
